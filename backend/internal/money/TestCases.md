# Сценарии денежного ядра

Все денежные значения в тестах — целые копейки. Команды: `make test-backend`, `make test-fuzz`.

| Сценарий | Тест |
|---|---|
| 100 на троих, меньше копеек, чем людей, ноль, один участник | TestAllocate |
| Веса 2:1; дробный остаток важнее порядка; максимальные допустимые сумма и веса | TestAllocate |
| Отрицательные/чрезмерные суммы и веса, MaxInt64, пустые назначения | TestAllocateInvalid |
| Чужие/повторные участники, повторный/некорректный порядок, лимиты состава | TestAllocateInvalid |
| Личная, общая, на всех, по единицам, по весам; своя доля плательщика | TestModes |
| Отсутствующая/отрицательная цена, нулевое/отрицательное количество, переполнение произведения и суммы | TestCalculateInvalid |
| Лимит строк, повторные/пустые ID, чужой плательщик, неверный итог чека | TestCalculateInvalid |
| Неизвестный режим, число единиц меньше/больше заказанного, некорректные назначения | TestCalculateInvalid |
| Неполный черновик, отсутствующий итог/плательщик, расхождение чека, пустая встреча | TestDraftAndFinalization |
| Бесплатная нераспределённая строка блокирует фиксацию; назначенная разрешена | TestDraftAndFinalization |
| «На всех» сохраняет выбранный состав после добавления участника | TestAllFreezesParticipants |
| Перестановка входов не меняет доли; входы и разные результаты не разделяют изменяемые данные | TestDeterminismAndInputOwnership |
| 17 реальных строк: независимая сумма 882000, точные итоги, остатки по пицце/чаю, возврат 757832 | TestRestaurant |
| Нет/частичный/полный возврат; отрицательные, нулевые, чрезмерные получения; долг плательщика 0 | TestRemaining |
| Сохранение суммы, детерминированность, перестановки, границы долей по big.Int | FuzzAllocate |
| Сумма черновика, видимость нераспределённого, готовность, сумма каждой строки | FuzzCalculate |
| Допустимые границы: 1000 участников, 10000 строк, максимальные количество и сумма | TestAcceptedLimits |
| Результат при ошибке не готов к фиксации | TestRejectedResultIsNotFinalizable |
| Произвольные int64 суммы и веса: валидные приняты, остальные отвергнуты без panic | FuzzInvalidNumbers |

`CalculateFinal` проверяет математическую готовность; тестов хранения неизменяемого снимка и аудита платежей здесь пока нет — это этап 3.
