# Разработка в Windows 11

Откройте D:\Projects\My\PoDolyam в обычном VS Code и PowerShell. Нужны нативные Go 1.27.1, Node 24.19+ ветки 24 и npm. Зависимости закреплены в go.mod/go.sum и package-lock.json. Проверенная локальная среда: Go 1.27.1, Node 24.19.0, npm 11.17.0. WebView2 необходим для запуска окна.

| Команда из корня | Действие |
|---|---|
| make help | Короткая подсказка с доступными командами |
| make test | npm ci, vet, Go/SQLite-тесты, 3 fuzz-прогона, typecheck, lint, Vitest |
| make build | npm ci, Vue-сборка, встраивание статики и build/PoDolyam.exe |

Makefile рассчитан на нативный GNU Make для Windows и вызывает внутренний .cmd-скрипт; менять PowerShell ExecutionPolicy не требуется. test и build сами устанавливают зависимости по lock-файлу. Перед пересборкой закройте ранее запущенный exe. Сборка перезаписывает только генерируемую копию frontend в backend/cmd/desktop/ui и exe в build.

## Go

Команды Go выполняются из backend, где находится go.mod. gofmt форматирует изменённые .go-файлы. Чистое ядро находится в internal/money; пояснения инвариантов — CALCULATIONS.md. go run ./cmd/demo выводит отдельный демонстрационный расчёт и не заполняет пользовательскую БД.

SQLite-тесты используют реальные временные файлы; отдельный сервер не нужен. Расширенный серверный integration-набор по build tag integration требует PostgreSQL и не входит в Windows test. Race detector проверяется отдельно в Linux CI для money/local.

## Версия приложения

APP_VERSION задаётся в корневом .env (пример — .env.example). Windows-сборка передаёт значение в Vite и показывает его в шапке рядом с Windows edition. Если .env отсутствует, локальная сборка использует значение из .env.example.

## Данные и схема

По умолчанию %LOCALAPPDATA%\PoDolyam\podolyam.db. Для изолированной ручной проверки задайте PODOLYAM_DATA_DIR абсолютным путём только в текущем терминале. Миграции SQLite до user_version=3 выполняются при открытии базы; версия 3 добавляет имя профиля и справочник друзей. Будущие миграции должны сохранять пользовательские данные и обновлять user_version транзакционно.

## Ручная проверка окна

1. Создать встречу, добавить Женю и Диму, плательщик Женя.
2. Личное блюдо 100 ₽ Жене и общее 100 ₽ на двоих; итог чека 200 ₽.
3. Сохранить, зафиксировать: Жене 150 ₽, Диме 50 ₽ к возврату.
4. Скопировать сообщение Диме, сформировать PDF-чек: только его общее блюдо и 50 ₽.
5. Записать 20 ₽, проверить остаток 30 ₽; отменить с причиной, убедиться в восстановлении остатка.
6. Записать полный возврат, закрыть встречу, перезапустить exe и проверить сохранность.

Эта процедура описана, но полный прогон окна и системных диалогов ещё не подтверждён автоматизацией.
