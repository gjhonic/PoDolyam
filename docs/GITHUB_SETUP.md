# GitHub

Удалённые настройки не изменялись. Текущий CI проверяет Windows-приложение и отдельно money/local с race detector на Linux. Итоговый required check: **CI required**. Workflow подготовлен локально; первый запуск на GitHub ещё требуется проверить.

## Подключение

Создание репозитория, коммит и push — только по отдельной просьбе. После подключения включите Actions с разрешением используемых действий. Достаточно contents: read: workflow не публикует релизы и не использует production-секреты. Зависимости кэшируются по go.sum и package-lock.json.

Для main настройте PR, обязательный CI required, запрет force push и удаления ветки. Выберите политику при фактической настройке:

- Командная: один независимый approve и успешный CI.
- Личная: успешный CI без обязательного чужого approve; автор не может одобрить собственный PR.

Существующие ruleset не ослаблять автоматически. Ветки feature/PD-<реальный номер>-описание; номера задач не выдумывать.

## Выпуск

Windows exe собирается в CI, но автоматическая публикация и подпись пока не включены. GHCR, production environment, VPS, SSH-секреты и домен для локального приложения не нужны. Если серверный вариант вернётся, его отдельный workflow и политика secrets потребуют новой настройки.
